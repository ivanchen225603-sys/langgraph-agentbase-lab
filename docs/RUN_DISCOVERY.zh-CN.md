# 通用运行索引

独立宿主已有提交、详情、取消、恢复和事件接口。本索引补上客户端丢失 Run ID、或宿主重启后按已认证主体查找记录的入口，不依赖旧 RAG 服务，不增加执行器。

## 接口与样例

```http
GET /api/v1/agents/{agent_id}/runs?limit=20&after=LAST_RUN_ID
Authorization: Bearer <host credential>
```

省略 `after` 从头查询；`limit` 默认 20，范围 1–50。

```json
{
  "runs": [{"run_id": "abc123", "agent_id": "example"}],
  "next_after": null
}
```

有后续记录时 `next_after` 为本页最后一个 Run ID；下一页原样传入。按 Run ID 字典序升序排列，**不是创建时间顺序**。这是实时索引，不提供跨页快照：并发新建记录如果落在游标之前，需从头刷新才能发现。游标只是排他排序边界，不能授予身份或访问权限。

状态、结果及其当前可见性仍通过原 `GET .../runs/{run_id}` 查询。索引只返回 `run_id` 与 `agent_id`，不投影结果、不读取 payload、不查询工具收据或来源、不触发执行/恢复/取消/审批。它不返回输入、幂等 key、会话、检查点、审批或结果正文，也不宣称记录仍可恢复。

## 权限与存储

owner 仅来自宿主认证。SQL 同时按 owner 与 Agent 过滤，再执行有界 keyset 查询；不接受 owner、状态过滤或 offset 参数，未知和重复参数拒绝。无当前发布的 Agent 与原注册接口一致返回 `unknown_agent`，不会搜索其他 Agent。

查询前后刷新原始请求凭据、当前运行身份及所有已装配的 Agent ACL；中途撤权、换主体、变更身份版本或刷新失败时整页拒绝。允许查看索引不授予工具 scope、结果来源权限或恢复权限，详情及控制继续使用原接口检查。

成功响应带 `Cache-Control: no-store`，并按 Authorization/Cookie 区分。此能力不新增表、迁移、自动清理或后台任务。同步 SQL 查询期间不能在同一事件循环插入 await；外部身份系统与 SQLite 之间仍不提供分布式原子撤权保证。

## 验收矩阵

| 场景 | 期望 |
|---|---|
| 空索引 | 空页，无 Run 或工具操作 |
| 多主体、多 Agent | 只返回当前主体及目标 Agent 的 ID |
| 分页、边界 | 有界、排他、无重复；页尾返回 null |
| 重复/未知/越界参数 | 明确拒绝，不扩大查询 |
| 凭据、身份或 ACL 中途变化 | 整页拒绝，不泄露已选 ID |
| 宿主重启 | 已有记录可发现，不重执行工具 |
| 结果和副作用 | 索引无正文、不调用详情投影，记录与操作状态不变 |


## 通用页面接线

通用 Agent 页现在通过“刷新运行列表 / 下一页”调用本索引，每页 20 条，单次查询超时 10 秒，不自动翻页。选择 ID 只设置候选；“查询所选运行”才调用原详情 GET，不提交任务或触发恢复。普通输入框仍支持明确填写 Run ID 后查询。列表属于当前主体，页面离开/恢复、Agent 或凭据变化会清空 ID、游标、审批及恢复状态，旧请求不能回填。

“恢复当前运行（无待审批）”仅在当前详情明确 `recoverable:true`、无待审批、无取消/收尾及可见性阻断时启用。点击后重新 GET 当前详情，再向同一 Run 的原 `resume` 接口发空正文；服务端仍复检身份、权限、状态和原期限。待审批必须使用原 `review_id/digest` 确认按钮，普通恢复不能代替批准。输入、会话、主题或手工 ID 编辑会使原控制状态失效。

恢复响应丢失或失败时显示“尚未核实”，禁止自动重发；须另行手动查询。订阅断开仍不取消后台 Run，原取消收尾观察继续保留。这些界面行为有模拟 DOM 与真实进程内 ASGI 序列验证，真实浏览器/bfcache 仍未验收，未重试此前被拒绝的原点。
